# Контролька — правила проекта

Учебное веб-приложение для школьников (сейчас 4 класс, «Школа России»). Чистые HTML/CSS/JS на ES-модулях, без фреймворков, сборщика и зависимостей. Публикуется на GitHub Pages.

## Команды

- `npm start` — локальный сервер http://localhost:8080 (`scripts/serve.js`). Через `file://` приложение не работает.
- `npm test` — автотесты `node:test` (`tests/*.test.js`).
- `npm run validate` — проверка всех учебных данных. Запускать после любой правки `data/`.

## Структура

- `js/quiz.js`, `js/results.js`, `js/storage.js`, `js/validate.js`, `js/customTests.js`, `js/utils.js`, `js/router.js` — логика **без DOM**, покрыта тестами. Новую логику класть сюда, а не в экраны.
- `js/state.js` (данные пользователя + загруженное содержимое), `js/session.js` (сессия ↔ хранилище), `js/data.js` (загрузка JSON), `js/ui.js` (DOM-хелпер `h()`, диалоги, уведомления), `js/components.js`.
- `js/screens/*.js` — экраны; `js/app.js` — маршруты (`#/имя/параметр`).
- `data/subjects.json` → `data/content/<предмет>-<класс>.json` (`topics` + `questions`). Формат описан в README.
- `css/styles.css` (токены, темы), `layout.css` (каркас, mobile-first, точки 600/1024 px), `components.css`.

## Правила

- Пользовательские строки только через `h()` / `textContent`. Никакого `innerHTML`, `eval`, `Function`.
- Не показывать нереализованные функции и не выдумывать результаты.
- Проверка ответов только по данным вопроса (`checkAnswer`), без ИИ. Числа — точное сравнение, если не задан `tolerance`.
- Данные в `localStorage` под ключом `kontrolka.data`, схема `SCHEMA_VERSION` в `storage.js`. Любые новые поля нужно добавлять и в `sanitizeData`.
- Учебные задания — только оригинальные тексты; учебники в репозиторий не класть. Новые задания добавлять с `"verified": false`.
- Интерфейс и комментарии на русском.

## Публикация и порядок работы

- **Push в `main` = публикация на сайт** (GitHub Pages), который открывают одноклассники. После коммита спросить: пушить или пока только закоммитить. Без явного «да» в `main` не пушить.
- Перед публикацией — коротко, по-человечески, четыре пункта: **как было**, **что сделано**, **что изменилось** для ребят, **на что повлияло** (например, сбросится ли что-то у пользователей). Сначала сводка — потом вопрос «публикуем?».
- **Ничего не удалять самому**: файлы, ветки, коммиты, опубликованное, данные в `uchebniki/`. Нужно удалить — предложить, назвать что именно и зачем; после «да» переспросить, перечислив, что не восстановится. Перезапись файла и `push --force` — тоже удаление.
- Крупная задача — сначала план. После шага сказать, что открыть и что там должно быть видно; не писать «должно работать».
- Не знаешь факт из предмета — не придумывать похожее, а проверить по учебнику в `uchebniki/` или спросить.
- Хук `.githooks/pre-commit` (включается `git config core.hooksPath .githooks`) не пускает в коммит PDF/учебники и коммит с упавшими `validate`/`test`.
- `uchebniki/` (учебники, тетради, демоверсии МЦКО, олимпиады) — только для сверки, в git и на сайт не попадает.
